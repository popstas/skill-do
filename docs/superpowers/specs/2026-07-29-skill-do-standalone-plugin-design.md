# Design: extract the `do` skill into a standalone multi-agent plugin

**Date:** 2026-07-29
**Status:** approved

## Problem

The `do` skill lived inside [`ai-slash-commands`](https://github.com/popstas/ai-slash-commands)
as `skills/do/`, sharing that repo's CalVer release train (`v2026.7.2`) with 16 unrelated slash
commands. The skill has its own release cadence, its own tests, and is worth installing on its own
— including from agents other than Claude Code. It needs its own repo, its own 0.x versioning, and
packaging for the current plugin conventions.

## Goals

- A standalone repo `~/projects/text/skill-do` → `github.com/popstas/skill-do` (public).
- The skill's commit history preserved, not squashed into an "initial import".
- Versioning restarted at 0.x: one minor release per historical feature series.
- Installable as a plugin from Claude Code, Codex, and Cursor without duplicating the skill body.
- `ai-slash-commands` keeps working exactly as before.

## Non-goals

- Removing `skills/do/` from `ai-slash-commands` (deferred — see Open questions).
- Publishing to npm.
- Carrying over the parent repo's plan docs (`docs/plans/completed/2026-05-*-do-skill.md`).

## Repo layout

```
skill-do/
├── .claude-plugin/
│   ├── plugin.json          # Claude Code plugin manifest
│   └── marketplace.json     # self-marketplace: /plugin marketplace add popstas/skill-do
├── .codex-plugin/plugin.json    # "skills": "./skills/"
├── .cursor-plugin/plugin.json   # "skills": "./skills/"
├── skills/do/
│   ├── SKILL.md             # the skill the agent reads
│   ├── README.md            # skill docs, incl. the statusline_block section
│   ├── statusline-block.sh  # ccstatusline custom command
│   └── tests/               # unittest: skill frontmatter + statusline-block.sh
├── scripts/release.mjs      # version bump across manifests + changelog + tag
├── .github/workflows/{test.yml,release.yml}
├── cliff.toml, CHANGELOG.md, README.md, LICENSE, docs/TODO.md
```

The three manifests are metadata only; all of them point at the single `skills/` directory, so the
skill body exists once. This mirrors how `superpowers` ships (`.claude-plugin/`, `.codex-plugin/`,
`.cursor-plugin/` side by side in one repo), verified against the installed plugin caches.

The plugin and the skill are both named `do`, so `/do` keeps working. The repo is named `skill-do`
because `do` alone is too generic for a repository.

## History extraction

`git clone --no-local` of the parent, then `git filter-repo --path skills/do`. Because the target
layout keeps the `skills/do/` prefix, no path rewriting is needed — the historical diffs are
byte-for-byte identical to the parent's. Nine commits survive; the parent's `v2026.*` tags are
deleted.

One commit message is rewritten. `a8e5a11 feat: add todo-review skill (#3)` was a squashed PR whose
only changes under `skills/do/` were `/do` flow edits; keeping that subject would put a false entry
("add todo-review skill") into this repo's changelog. It becomes
`docs(do): expand /do flow with planning and push`, with a body noting the origin PR. All other
messages are untouched.

## Versioning

The skill is pre-release, so versioning restarts at 0.x. Each historical feature series — a run of
commits landed on one day — becomes one minor release, tagged as an annotated tag whose date
matches the commit:

| Tag | Date | Content |
|---|---|---|
| v0.1.0 | 2026-05-28 | first cut: TODO evaluation, cron, Telegram |
| v0.2.0 | 2026-06-01 | planning step before adopt, e2e question, exec bits |
| v0.3.0 | 2026-06-02 | clear completed todos, `do finalize` |
| v0.4.0 | 2026-06-06 | `do early pr`, TODO edits folded into code commits |
| v0.5.0 | 2026-06-09 | checklist for manual feature checks |
| v0.6.0 | 2026-07-02 | drop cron/telegram, ralphex-plan, tiered planning modes |
| v0.7.0 | 2026-07-29 | `statusline_block` for ccstatusline |

Three-part semver (`0.1.0`, not `0.1`) because the plugin manifests carry a `version` field that
tooling parses as semver. `0.7.0` is the current version; the next release is `0.8.0`.

`CHANGELOG.md` is generated by `git-cliff` from these tags, reusing the parent's `cliff.toml`.

## Release machinery

`scripts/release.mjs` — adapted from the parent's release script:

1. refuse to run on a dirty tree;
2. bump `version` in all three `plugin.json` files to the requested 0.x version;
3. regenerate `CHANGELOG.md` via `npx git-cliff`;
4. commit `chore(release): v0.N.0` and create the annotated tag;
5. push only with `--push`.

The version lives in three manifests, so the script is the single writer — hand-editing them is how
they drift.

CI (`.github/workflows/`):

- `test.yml` — run `python3 -m unittest discover skills/do/tests` on push and PR.
- `release.yml` — on a `v*` tag, create the GitHub release with git-cliff notes.

## Testing

The skill's existing tests move with it and stay the contract:

- `tests/test_skill_meta.py` — `SKILL.md` frontmatter (name, description, argument-hint) and
  documented flows.
- `tests/test_statusline_block.py` — `statusline-block.sh` output for plain/split modes, missing
  file, no checkboxes, env overrides.

Run: `python3 -m unittest discover skills/do/tests`. No JS test suite — there is no JS to test.
`test_skill_meta.py` gains assertions that the three manifests exist, parse as JSON, and agree on
`version` and `name`, so a partial release cannot pass CI.

## Effect on `ai-slash-commands`

Nothing changes there in this work. `skills/do/` stays, `scripts/gen.mjs` keeps generating the
`/do` command shims, and its tests keep passing.

**Known collision:** installing this plugin into Claude Code while `ai-slash-commands` also
installs `~/.claude/skills/do` gives two skills named `do`. Therefore this work publishes the repo
but does **not** install the plugin locally. Cutting over means removing the copy from the parent
(or dropping `skills/do` from its install list) in a separate change.

## Open questions

- Fate of `skills/do/` in `ai-slash-commands` — kept for backward compatibility for now, decided
  later.
- Whether to also ship Gemini/Antigravity and opencode packaging (`gemini-extension.json`,
  `.opencode/`) as `superpowers` does. Deferred until needed.
